## 7. 任务状态定义

| 状态 | 使用条件 |
|---|---|
| 待开始 | 已纳入范围，尚未开始执行 |
| 进行中 | 当前正在执行，尚未满足完成条件 |
| 已完成 | 任务验收条件均有证据支持 |
| 已阻塞 | 存在无法由当前执行步骤解决的明确依赖或外部条件，必须记录解除路径 |
| 待恢复 | 已启动但因明确的主线顺序暂时不执行；保留未完成项，恢复时重新设为进行中 |
| 已取消 | 经明确决策从范围中移除，并记录原因 |

“代码已提交”“测试代码已存在”“CI 跳过”“方案已写入文档”均不能单独作为已完成依据。需要真实环境验收的任务，必须有真实环境结果；没有证据时保持进行中或已阻塞，不得虚报完成。

- **文档索引.md**：维护文档入口和职责边界。

任务切换必须在同一组文档变更中完成：
1. 验收当前任务并记录证据。
2. 将整体规划中的对应任务标记为已完成，并关联归档文件。
3. 将当前任务完整归档到任务历史。
4. 将下一任务设为进行中，并更新当前任务.md。
5. 检查所有链接和状态一致性。

历史记录只作追溯，不得重新成为任务状态来源。已有功能缺陷仍由《未关闭问题与后续验收》维护其缺陷证据；新产品能力任务状态统一由本文维护。

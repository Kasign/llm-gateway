## 1. 目标

完成 TOOL-01～TOOL-08 的真实部署闭环验收，确认 Gateway 部署环境中工具授权、执行失败、旁路拒绝和审计脱敏行为符合预期。TOOL-09 未完成前不启动 BENCH-05。

## 2. 已有证据（不可重复做）

- Gateway 容器访问真实 SearXNG 已验证。
- 用户提供过真实模型触发 `web.search` 并产生审计事件的成功证据。
- 工具定义、Runtime、Coordinator、非流式闭环、Key ACL、管理配置和审计链路已有 Go CI / Browser Smoke 覆盖。
- 统一模型测试入口及共享客户端 Key 鉴权已合并到当前分支。

## 3. 本轮验收范围

1. **授权成功**：具备 `web.search` 权限的调用方 Key 可以触发真实工具调用，工具事件和请求审计关联正确。
2. **授权拒绝**：无工具权限、Key 禁用/撤销或工具未授权时 fail closed；不得退化为直接执行工具。
3. **执行失败**：SearXNG 不可达、上游错误、超时和工具结果异常时，模型请求按既定错误语义结束，审计记录失败类别且不泄露凭据。
4. **旁路拒绝**：普通模型请求、Benchmark 普通性能场景或不满足工具调用条件时，不得绕过 Coordinator/ACL 直接执行工具。
5. **审计脱敏**：工具参数、结果、错误、请求头及日志中不得泄露调用方 Key、管理凭据或敏感配置；审计仍保留必要的工具名、状态、耗时和错误分类。
6. **真实部署回归**：在实际 Gateway 部署配置下确认容器网络、工具配置、Key 权限与模型工具调用完整闭环。

## 4. 执行约束

- 先审查现有实现和已有测试，按缺口补验，不重复实现 TOOL-01～TOOL-08。
- 不改变普通 `/v1/chat/completions` 请求协议与主流程，不放宽工具 ACL，不使用真实有副作用工具进行测试。
- 不在文档、CI 日志或提交中写入真实 API Key、密码、Cookie、完整 Authorization 或私有响应负载。
- 自动化环境验证与真实部署验证分别记录；CI 通过不能代替真实部署验收。
- 如果真实部署步骤必须由用户在服务器执行，只提供最少必要命令并明确需回传的脱敏证据。

## 5. 验收输出

- 每项记录：pass / fail / blocked / not_applicable、执行环境、证据引用和缺口。
- 失败路径至少覆盖权限拒绝、工具超时/上游失败及审计脱敏。
- 真实成功调用与拒绝/失败事件均可关联到请求 ID，且不包含凭据。
- 全部通过后归档 TOOL-09，再进入 BENCH-05。


## 6. 代码侧 Review 结果

- `forwardWithTools` 仅在工具全局启用、Chat Completions、非流式、模型 ACL 通过且当前调用方 Key 授权工具交集非空时进入 Coordinator；显式工具意图但缺少 Key 授权时返回 403，不回退执行。
- Runtime 缺少 Authorizer、授权依赖报错或拒绝时均 fail closed；工具执行超时、取消、并发限制、无效结果和 Executor panic 有稳定错误分类。
- Provider/Executor 原始错误不直接返回调用方；审计事件只保存工具名、轮次、状态、耗时、结果字节数和稳定错误码，不保存 arguments、搜索词、结果正文、调用 ID 或原始错误文本。
- 请求头在实时详情和 payload 持久化前统一脱敏；覆盖 Authorization、API Key、Cookie、Token、Secret、Credential、Signature 及常见厂商凭据头。
- 已有自动化覆盖：无 Key 工具授权拒绝、模型 ACL、Runtime 授权不可用/拒绝、工具超时、Provider 非 2xx、普通请求旁路、工具事件敏感字段不落库、请求头脱敏。
- 当前分支代码 Review 未发现需要为 TOOL-09 重复实现的公共能力；不改工具主链路。

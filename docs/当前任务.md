## 1. 目标

完成 Benchmark 管理台场景配置、任务历史列表、执行明细、状态恢复和历史比较。普通性能测试与工具调用性能测试共用任务生命周期；工具功能测试仍保持独立协议与目标。

## 2. 已有实现

- 页面入口位于 web/index.html 的“模型测试”区域；当前有“性能测试”和“工具测试”两个模式。
- 普通性能模式调用 POST /api/benchmark，轮询 GET /api/benchmark/{id}，显式停止使用 DELETE；job_id 和参数恢复逻辑已存在。
- 页面导航不会取消服务端任务；客户端 Key 只保存在页面内存，不写 localStorage/sessionStorage。
- 工具功能测试是独立的一次性请求，不是 Benchmark Task。
- BENCH-05 已新增 scenario=tool_performance，强制 web.search 非流式工具闭环；状态 API 返回 tool_call_events 和 tool_metrics。
- Benchmark Task/Run 已持久化；BenchmarkRepo 有 GetTask/ListRuns，但当前尚无历史 Task 列表和比较 API。
- 当前结果页能展示普通性能请求分析、条件可比性、响应与流式事件；尚未展示工具性能阶段指标和工具事件。

## 3. 实施顺序

1. 审查 web/index.html、web/js/app/main.js、Benchmark API/OpenAPI、BenchmarkRepo 和 Browser Smoke；确认当前交互、状态恢复和历史查询缺口。
2. 设计历史列表 API：分页、状态/场景筛选、按时间排序；不返回密钥或 Prompt 正文。
3. 设计历史比较规则：仅同场景、条件指纹完整且一致的任务可作严格比较；partial/unknown 必须显示不可严格比较及缺失原因；不同场景不混比。
4. 增加工具性能场景入口和专用提示词；继续使用共享客户端 Key 内存态，显式要求 web.search 权限。
5. 增加任务历史列表、详情和工具阶段指标展示；展示服务端 tool_metrics 与工具审计事件，不在前端重新计算指标。
6. 增加历史比较视图；指标与可比性结论由服务端提供，前端只负责呈现。
7. 补齐刷新/导航/恢复/取消/失败状态测试，更新 Browser Smoke、OpenAPI 和文档。

## 4. 不可破坏的约束

- 不改普通 /v1/chat/completions 的协议、认证、Pipeline、Provider、流式响应、错误处理和取消时序。
- 不通过 HTTP loopback 调用自身 API。
- 不改变工具触发、Key ACL、模型 ACL、工具执行和审计脱敏逻辑。
- 页面切换、刷新或关闭不得取消服务端任务；取消只能由用户显式触发。
- 不把客户端 Key 写入 localStorage/sessionStorage；历史记录不保存 Key 明文。
- 不把 Prompt、Answer、Reasoning 或工具 arguments/结果正文复制进 Benchmark 表。
- 不在前端自行计算性能指标；不将 unknown/not_applicable 显示成 0。
- 不同场景、不同模型/Provider/参数或不完整条件不得显示为严格可比。
- 不自动重放中断任务；不制造演示数据或假历史记录。

## 5. 验收标准

- 可选择普通性能与工具调用性能场景，工具性能请求明确绑定 web.search。
- 可查看历史任务、场景、模型、状态、时间、端到端指标和条件完整性。
- 可从历史列表打开完整执行明细；工具场景显示模型决策、工具执行总耗时、最终生成、轮数/调用数和单次工具事件。
- 页面刷新或重新进入后能恢复活动任务轮询；显式取消能正确反映终态。
- 历史比较严格遵守场景和条件指纹规则；不可比任务显示原因，不强行给出性能结论。
- 客户端 Key 仅内存使用；前端不存储敏感凭据。
- Go CI、Browser Smoke 通过；TOOL-09 真实部署验收留待后续统一回归。

## 3. 本轮验收范围

1. **授权成功**：具备 `web.search` 权限的调用方 Key 可以触发真实工具调用，工具事件和请求审计关联正确。
2. **授权拒绝**：无工具权限、Key 禁用/撤销或工具未授权时 fail closed；不得退化为直接执行工具。
3. **执行失败**：SearXNG 不可达、上游错误、超时和工具结果异常时，模型请求按既定错误语义结束，审计记录失败类别且不泄露凭据。
4. **旁路拒绝**：普通模型请求、Benchmark 普通性能场景或不满足工具调用条件时，不得绕过 Coordinator/ACL 直接执行工具。
5. **审计脱敏**：工具参数、结果、错误、请求头及日志中不得泄露调用方 Key、管理凭据或敏感配置；审计仍保留必要的工具名、状态、耗时和错误分类。
6. **真实部署回归**：在实际 Gateway 部署配置下确认容器网络、工具配置、Key 权限与模型工具调用完整闭环。

## 8. 真实部署验收操作步骤

以下步骤在独立测试窗口执行。先确认部署版本与当前 `dev` 验收基线一致；若线上尚未部署该版本，先按项目 1Panel 部署说明更新并确认容器健康。不要在生产流量高峰做故障注入。

### 8.1 配置与前置检查

1. 在 `config.yaml` 中启用工具，并只开放本轮验收需要的工具：
   - `tools.enabled: true`
   - `tools.allowed_tools: ["web.search"]`
   - `tools.searxng.base_url` 指向 Gateway 容器可访问的 SearXNG 内部地址。
2. 若 SearXNG 使用 Docker 私网地址，只有在确认该地址属于受控 Docker 网络和可信服务后，才将 `allow_private_network` 设为 `true`；不要为了通过测试而开放任意目标。
3. 确认 SearXNG 在 Gateway 容器网络内可达。工具超时默认 8 秒；验收请求不应长时间占用模型。
4. 在服务密钥管理页创建两把临时测试 Key，使用相同的 `allowed_models`：
   - `TOOL_ALLOWED_KEY`：授予 `web.search`。
   - `TOOL_DENIED_KEY`：不授予任何工具。
   测试结束后禁用并删除两把临时 Key。
5. 确认目标模型在 `GET /v1/models` 返回的目录中，且两把 Key 均有权访问该模型。

### 8.2 准备请求

在部署机终端创建临时请求文件（替换模型 ID；不要把 Key 写进文件）：

```bash
cat > /tmp/tool09-request.json <<'JSON'
{
  "model": "REPLACE_WITH_ACTIVE_MODEL_ID",
  "messages": [
    {"role": "user", "content": "请使用 web.search 搜索 OpenAI 官方网站的最新开发者文档，并总结结果。"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "web.search",
        "description": "Search the web",
        "parameters": {
          "type": "object",
          "properties": {"query": {"type": "string"}},
          "required": ["query"],
          "additionalProperties": false
        }
      }
    }
  ],
  "tool_choice": {
    "type": "function",
    "function": {"name": "web.search"}
  },
  "stream": false
}
JSON
```

客户端提供的工具定义只表达调用意图，服务端仍使用 Registry 中的定义和 Key ACL 执行；它不能改变实际工具实现。

### 8.3 授权成功与拒绝

在当前 Shell 安全读取临时 Key，避免将 Key 写入命令历史：

```bash
read -rsp "Allowed test key: " TOOL_ALLOWED_KEY; echo
read -rsp "Denied test key: " TOOL_DENIED_KEY; echo
export TOOL_ALLOWED_KEY TOOL_DENIED_KEY
```

授权 Key：

```bash
curl -sS -D /tmp/tool09-allowed.headers -o /tmp/tool09-allowed.json \
  -w 'HTTP %{http_code}\n' \
  http://127.0.0.1:8088/v1/chat/completions \
  -H "X-API-Key: $TOOL_ALLOWED_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/tool09-request.json
```

预期：HTTP 200，响应为最终模型答复；请求详情中存在关联的 `web.search` 成功事件（`status=succeeded`），且有合理的执行耗时和结果字节数。

无工具授权 Key：

```bash
curl -sS -D /tmp/tool09-denied.headers -o /tmp/tool09-denied.json \
  -w 'HTTP %{http_code}\n' \
  http://127.0.0.1:8088/v1/chat/completions \
  -H "X-API-Key: $TOOL_DENIED_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/tool09-request.json
```

预期：HTTP 403，错误码 `tool_not_allowed`；SearXNG 不应收到该请求。若返回 `tool_model_not_allowed`，先检查两把 Key 的模型 ACL 是否一致，不要把它记作工具 ACL 验收通过。

### 8.4 普通请求旁路

使用授权 Key 发送不包含 `tools` 和 `tool_choice` 的普通 Chat Completions 请求。预期正常返回模型结果，关联请求的工具事件为空；不能因为工具全局启用而自动触发工具。

### 8.5 上游失败与审计脱敏

在独立测试环境中暂时停止 SearXNG，或将测试环境的 SearXNG 地址临时指向一个不可达的受控测试端点，再使用授权 Key 重复 8.3 的强制工具请求。预期请求以非成功状态结束，工具事件记录失败/超时状态和稳定错误分类；恢复 SearXNG 后再确认成功调用恢复。不要在共享生产实例停止 SearXNG。

完成后检查请求详情、工具事件和 Gateway 日志：
- 请求详情能关联同一个 request ID；事件只包含工具名、轮次、状态、耗时、结果字节数和稳定错误码。
- 不包含调用方 Key、Authorization、Cookie、SearXNG 凭据、原始 arguments/query、结果正文或原始上游错误。
- 对普通请求不应产生工具事件。

### 8.6 回传结果

仅回传以下脱敏信息，不要回传 Key、完整响应正文、搜索词或完整 Header：
- 当前部署 commit / 镜像版本；
- 授权请求 HTTP 状态、错误码（若有）、request ID、工具事件状态/耗时/结果字节数；
- 无授权请求 HTTP 状态与错误码；
- 普通请求 HTTP 状态及工具事件数量；
- 故障注入请求 HTTP 状态与工具事件错误分类；
- 恢复后再次调用的结果。

验收通过后禁用并删除临时 Key，删除 `/tmp/tool09-*` 文件并取消 Shell 环境变量：
`unset TOOL_ALLOWED_KEY TOOL_DENIED_KEY`。

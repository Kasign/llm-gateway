## 1. 目标

在现有 Benchmark Task/Run、请求分析和工具审计基础上，建立真实可解释的非流式工具调用性能测试能力，分别测量模型决策、工具执行、模型最终生成和端到端耗时。不得改变普通 /v1 请求语义或工具权限/执行逻辑。

## 2. 用户决策与阶段边界

- 用户明确要求先继续后续开发，TOOL-09 真实部署验收留待后续统一验证。
- TOOL-09 标记为“待恢复”，不是已完成；已有 SearXNG 连通和历史成功调用证据保留，授权拒绝、故障注入、旁路及审计脱敏的真实部署证据仍待补。
- 本次顺序调整只放行 BENCH-05 的代码实现和自动化验证；在最终整体验收前仍须完成 TOOL-09 真实部署回归。
- 不使用生产环境故障注入，不在自动化测试中依赖真实 API Key 或真实外部服务。

## 3. 已有实现与复用边界

- internal/tools/coordinator 已有 Result.ModelRounds / ToolRounds / ToolCalls / RoundUsage，以及工具事件 Round / Status / DurationMS / ResultBytes / ErrorCode。
- internal/server/tool_model_caller.go 负责单轮非流式模型请求；Coordinator 负责多轮模型—工具循环。
- request_tool_call_events 已保存工具事件元数据，并关联请求 ID；不得另建重复审计表。
- Benchmark 已有 Task/Run 持久化、请求 ID 关联、模型加载/推理耗时、TTFT 和条件快照；当前 Benchmark 请求固定为流式普通请求，尚不能进入非流式工具路径。
- BENCH-04 已明确未知/不适用指标状态，不允许将缺失值填 0。

## 4. 本阶段实施顺序

1. 审查 Benchmark 请求构造、Worker 执行边界、Coordinator 事件、工具事件持久化与请求详情 API，确认可复用数据和真正缺失的阶段指标。
2. 明确工具场景的请求配置、模型轮次计时边界和指标来源；区分模型调用墙钟耗时与工具执行耗时，避免把网络等待重复累计。
3. 设计最小 Task 场景扩展与 Run 指标输出；优先复用现有 request ID、工具事件和 Request Analysis。
4. 实现服务端工具场景适配，不复制 Coordinator、不通过 HTTP loopback 调用自身 API、不绕过 Key/模型 ACL/工具 ACL/Provider 限流。
5. 补齐单元、集成、竞态与回归测试；普通请求、流式、工具调用、权限拒绝、限流、取消的既有行为必须保持。
6. 更新 OpenAPI、配置/产品文档、前端展示（若本任务范围需要），运行 Go CI 与 Browser Smoke。

## 5. 不可破坏的约束

- 普通 /v1/chat/completions 的认证、请求解析、Pipeline 阶段、Provider 选择、流式响应、错误处理和取消时序不得因 Benchmark 改造改变。
- 不允许 Worker loopback HTTP 调用 /v1/chat/completions。
- 不改变工具触发、权限判断、参数校验、工具执行和审计脱敏逻辑。
- 只有行为等价的公共能力可以抽取；Benchmark 使用独立适配层。
- 不得将 Task 总耗时、模型加载、各轮模型调用、工具执行和端到端耗时混为同一指标。
- 不得从工具事件时间戳推导缺失的模型轮次耗时；必须有可靠计时来源。
- 工具失败、拒绝、超时及取消必须保留稳定状态；未知指标为 null + unknown/not_applicable。
- 不增加无明确场景的 API、字段、表或重复存储。

## 6. 验收标准

- 每个工具场景 Run 可关联唯一 Request ID 和已有工具事件。
- 能分别展示模型轮数、工具轮数、工具调用数，以及可可靠采集的每轮模型耗时、工具耗时、最终生成耗时和端到端耗时。
- 指标有明确定义、来源和计时边界；缺失项明确标记，不造数。
- 工具 ACL、模型 ACL、Provider 限流、请求取消和现有审计行为保持。
- 普通 /v1 请求回归无行为变化。
- Go CI、Browser Smoke 通过；真实部署验收仍由 TOOL-09 统一回归覆盖。

## 7. 当前调查结论

- Coordinator 已产生每次工具调用的 DurationMS，但目前未在 Result 中汇总每轮模型调用耗时。
- Result.ModelRounds 和 RoundUsage 仅提供轮数与 usage，不包含模型请求开始/结束时间。
- 现有工具事件表可作为工具执行耗时来源；模型轮次耗时需要在 Benchmark 适配层取得可靠时间，不能将其伪装成已有字段。
- 现有 Benchmark 默认流式请求，工具 Coordinator 只支持非流式；工具场景必须独立构造受控请求，并复用既有执行/鉴权边界。

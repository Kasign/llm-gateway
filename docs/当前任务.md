## 3. 已确认的指标缺口

审查文件：`internal/server/benchmark.go`、`internal/server/benchmark_persistence.go`、`internal/store/benchmark.go`、`internal/server/request_analysis.go`、`internal/server/pipeline_hooks.go`。

1. Worker 在 Pipeline 前执行 `InferenceLoad` 和 `WaitUntilModelReady`，但 `core.Request.Started` 和 `benchRunObserver.started` 使用 Task 创建时间。
2. 当前 TTFT 从 Task 创建时间计算，包含模型加载/就绪等待，不能代表模型请求发出后的首 token 延迟。
3. 当前 Task `latency_ms` 是从任务创建到完成的总耗时；应保留该兼容语义。
4. `benchmark_runs` 已有 `model_load_ms`、`inference_latency_ms` 列，但 `persistenceRecords` 尚未写入这两个字段。
5. `RequestAnalysis` 已提供 Prep、Model Load、Upstream、TTFT、首字节和吞吐指标；优先复用，不复制第二套阶段分析。
6. Request Analysis 的 `model_load_ms` 是 Pipeline 内 `PreparedAt → ReadyAt`，不包含 Benchmark 在 Pipeline 前的模型加载/就绪过程；两者必须区分。

## 4. 指标语义（实施前必须保持）

| 指标 | 定义 | 来源/边界 |
|---|---|---|
| Task 总耗时 | Task 创建至终态 | `job.StartedAt → FinishedAt`；保留现有 `latency_ms` 语义 |
| 模型加载/就绪耗时 | Benchmark Worker 执行模型加载与就绪等待的实际时间 | `InferenceLoad → WaitUntilModelReady`；不适用或无法测量时不能填 0 |
| Run 推理耗时 | 一次 `core.Pipeline.Run` 的墙钟耗时 | Pipeline 调用前至返回；包含 Gateway Pipeline 阶段和上游往返，不等同纯模型 Decode |
| TTFT | Pipeline 开始后首次收到非空 reasoning/content 的时间 | 从 Run 开始计时；不得包含模型加载和就绪等待 |
| 生成速度 | 真实 completion token 数 / 正文生成窗口，或可信 Provider timings | 复用 Request Analysis；缺少真实 usage/timings 时标记未知，不造数 |

说明：
- `model_load_ms` 仅在该 Provider/Backend 确实支持可测量的模型加载/就绪生命周期时标记 measured；远程 Provider 不具备该语义时标记 not_applicable。
- 未启动 Pipeline 的失败任务，其 Run 推理耗时和 TTFT 应为 unknown，而不是 0。
- 模型加载失败但确实执行过加载请求时，仍记录已测得的加载耗时。
- `latency_ms` 继续表示 Task 总耗时；不能悄悄改成 Pipeline 耗时。

## 5. 实施范围

- `internal/server/benchmark.go`：独立记录模型准备起止、Pipeline 起止；将 Benchmark TTFT 起点改为 Run 开始时间；保留 Task 开始时间。
- `internal/server/benchmark_persistence.go`：将已测得的模型准备耗时和 Pipeline 耗时写入 Run；未知值保持 NULL。
- `internal/store/benchmark.go`：审查 nullable 字段的 Go 表达，确保 unknown 与 0 可区分；优先复用现有列，除非状态表达确有缺口。
- Benchmark 查询 DTO / `docs/openapi.yaml`：按需暴露 `model_load_ms`、`inference_latency_ms` 及其可用性状态。
- `internal/server/performance_benchmark_test.go`、MariaDB 集成测试：覆盖冷热加载阶段、Pipeline 起止、提前失败、超时/取消和历史恢复。

## 6. 不可破坏的约束

- 不改普通 `/v1` Handler 的认证、请求解析、流式写回、取消时序。
- 不改变 `core.Pipeline.Run` 阶段顺序，不为计时额外增加 HTTP loopback。
- 不把 Pipeline 总耗时标成模型 Decode 时间。
- 不把缺失指标写成 0；unknown 与 not_applicable 必须区分。
- 不重复存储 Prompt、Response、流事件或工具事件。
- 中文注释、文档和提交说明；按可独立 Review 的功能组提交。

## 7. 验收条件

1. Task 总耗时与 Run 推理耗时可以独立查询，且旧 `latency_ms` 含义保持不变。
2. TTFT 从 Run 开始计时，不包含模型加载/就绪时间；首 token 未出现时保持 unknown。
3. 模型加载指标只在适用场景填充；未知与不适用不会被写成 0。
4. Run 指标在 MariaDB 持久化、历史查询和 Gateway 重启恢复后语义一致。
5. Request Analysis 的既有阶段字段和吞吐计算未被重复实现或破坏。
6. Go CI、MariaDB 集成测试、竞态测试、静态检查和 Browser Smoke 通过。

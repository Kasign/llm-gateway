## 1. 目标

定义并实现最小、可扩展的免费模型元数据结构，使后续 FREE-04 目录 API、FREE-05 管理台和 FREE-09 过期治理共用唯一数据契约。

本任务必须严格分离：

1. Provider 身份与接入配置；
2. 模型能力元数据；
3. 免费计划/免费政策；
4. 免费计划与具体模型的适用关系及模型级额度；
5. 官方证据、核验时间和有效期。

不得把免费政策塞进 Provider API Key 配置，不得把免费额度与 Gateway 实际 Token 使用量混为一谈。

## 2. 必须覆盖的元数据

### 2.1 Provider 与 Model 能力

- Provider ID、展示名、官方主页。
- Model ID、展示名、官方模型页。
- 支持协议：Chat Completions、Responses、Anthropic Messages 等。
- 能力：Streaming、Tool Calling、Vision、Structured Output、Reasoning、Embeddings 等。
- 上下文窗口、最大输出 Token：只有官方明确值才填写。
- Provider/Model 的地区可用范围与验证状态。
- 模型能力和协议能力必须分开，不能从 Provider 的 Chat Completions 支持推断每个模型都支持 Tool Calling。

### 2.2 Free Plan

- 免费类型：持续免费层、每日免费额度、免费模型变体、限时试用、付费订阅附赠额度、一次性赠送、已失效。
- 计划状态：有效、待复核、已变更、已失效、已撤回。
- 注册/账户/组织条件。
- 绑卡、手机号、组织认证等要求。
- 适用国家/地区。
- 数据留存、训练使用和服务条款提示。
- 生效时间、失效时间、最后核验时间、下次复核时间。

### 2.3 Plan-Model 适用关系与额度

- 一个 Provider 可有多个 Free Plan；一个 Free Plan 可覆盖多个 Model。
- 同一 Plan 下不同 Model 的免费资格和额度可以不同。
- 限额必须保留原始计量单位：请求、Token、Neurons、美元 Credits 等。
- 限额维度至少能表达 RPM、RPD、TPM、TPD、并发、每日 Neurons、Credits 余额/周期。
- 限额作用域要区分 Provider、Model、API Key、Project、Organization、Account。
- 周期必须明确：分钟、小时、日、月、试用有效期或不重置。
- 未知与 0 必须区分；未知字段不得写 0。
- 不把不同单位换算成一个“免费额度总数”。

## 3. 证据契约

每项关键政策事实都应能追溯到官方来源：

- 来源 ID、官方 URL、来源类型（官方文档/价格页/控制台/公告/条款）。
- 核验时间、适用时间范围。
- 该来源支持的字段或结论。
- 未知/冲突信息及说明。
- 下次复核时间。

没有来源的字段保持未知；第三方比较文章不得作为政策事实来源。

## 4. 存储与运行约束

先审查现有 Settings、MariaDB、静态配置加载和服务启动装配，再决定唯一权威存储方式。

设计原则：

- 个人使用规模优先，避免为了小目录新增复杂服务或重复数据表。
- Provider API Key 仍由现有加密流程保存；目录元数据不保存 Key。
- 免费目录读取不得进入推理热路径，不得影响已配置 Provider 的请求。
- 目录 API 只读；更新政策通过明确的权威数据更新流程，不允许 WebUI 自行猜测额度。
- 不建立第二套 Provider Registry；目录 Provider ID 必须引用现有 Provider ID。
- 不把本地模型 Catalog、远程模型目录和免费政策目录混成一个业务对象。

1. 完成现有存储和启动装配审查，说明为什么选用某一种存储方式。
2. 形成 Go 类型定义、JSON/API DTO 和校验规则；必要时增加最小样例数据。
3. 明确 Provider、Model、FreePlan、PlanModel、Quota、Evidence 之间的关系。
4. 对 FREE-02 六家候选数据做结构映射演示，重点验证模型级限额、Neurons、试用有效期、免费模型变体、地区与绑卡要求。
5. 不在本任务接入真实 API Key，不做真实推理请求。
6. 更新产品技术方案和整体任务规划，保持单一权威定义。

## 5.1 已完成的现状审查与第一轮修正

- 当前分支已有 `internal/freecatalog`，包含版本化 Catalog、Provider、Model、Plan、PlanModel、Quota、Evidence 类型、嵌入式 JSON、引用关系校验和有效状态推导；本任务继续完善，不另建平行目录实现。
- 现有 `internal/settings.Repo` / `gateway_settings` 保存运行时可变配置，远程 Provider 的 API Key 在该路径加密保存；免费政策属于审核后随版本发布的静态事实，不写入 Settings。
- 现有 `internal/catalog` 负责 Hugging Face / Ollama 本地模型发现，不承载远程 API 免费政策。
- 数据库迁移当前没有免费目录表；本任务不增加迁移。
- 已发现额度数值原先使用 `float64`，无法可靠保留高精度美元 Credits 小数。第一轮修正将额度数值改为 `json.Number`，用十进制有理数校验，避免浮点舍入；补充小数精度往返和非法/负数测试。
- 目录 Provider 是政策目录中的厂商身份，不代表已配置运行时 Provider；目录读取不触发网络调用、不读取 Key、不创建远程 Provider。

## 5.3 六家候选的首轮结构映射与账号要求

目录样例已写入 `internal/freecatalog/catalog.json`，当前包含 6 个 Provider、5 个可用/试用计划、5 个有官方 ID 证据的模型记录和 24 条官方证据。未知模型 ID 不猜测、不用展示名称伪造。

| Provider | 是否需要账号 | API Key / 凭证 | 免费层绑卡要求 | 目录处理 |
|---|---|---|---|---|
| Google AI Studio | 需要 Google 账号和活跃 Project | 在 AI Studio 为 Project 创建 API Key | Free Tier 不要求付费 Billing；部分导入 Project 可能需要验证 | 持续免费层；项目/模型额度保留未知并提示控制台核验 |
| GroqCloud | 需要 Groq 账号/组织 | 控制台创建 API Key | 官方公开文档未明确，标记 unknown | 持续 Free Plan；已知模型限额按模型关联 |
| Cloudflare Workers AI | 需要 Cloudflare 账号和 Workers Account | 使用账户 ID 与 API Token | Workers Free 基础额度不要求付费计划；部分模型要求 Paid，标记 conditional | 每日 10,000 Neurons；不换算成 Token |
| OpenRouter | 需要 OpenRouter 账号 | 创建 API Key | `:free` 模型无需购买 Credits；其他零价模型可能要求余额 | 免费模型变体；20 RPM / 50 RPD |
| Cerebras | 需要 Cerebras 账号 | 创建 API Key | **必须添加已验证付款方式**，5 美元/30 天试用 | 仅试用，不计入持续免费候选 |
| Hugging Face | 需要 HF 账号才能使用账户服务 | Token 用于认证 | Free 用户 Inference Providers 月度 Credits 为 0 | 记录 Provider 身份和排除证据，不伪造免费 API Plan |

这里的“需要账号”与“需要 API Key”是两个层次：账号用于接受条款、创建项目/组织和管理额度；API Key/Token 是程序请求凭证。免费目录本身只记录政策，不要求用户现在注册账号、生成 Key 或把 Key 提供给 Gateway。以后真正启用某个 Provider 时，才由用户在 Gateway 现有 Provider 设置中自行配置凭证。

当前目录刻意不把 Google 的动态模型额度、Groq 未确认的绑卡政策、Cloudflare 的模型级付费资格和 OpenRouter 动态免费模型集合写成确定值。Hugging Face Free 用户没有 API Credits，因此不创建虚假的免费计划。

## 6. 验收标准

- 免费政策和模型能力完全分离。
- 模型级额度和 Provider 级额度不会混淆。
- 请求、Token、Neurons、美元 Credits 等单位可原样表达。
- 未知、0、无限制、未公布、待复核等状态语义明确。
- 有效期和证据来源可追溯。
- 不重复创建 Provider 身份、Provider Key 或推理 Registry。
- 存储方案与个人使用规模匹配，没有无必要的数据库迁移或平行实现。

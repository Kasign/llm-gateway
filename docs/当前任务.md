## 3. 当前发现与外部依赖

- 仓库中的 `config.yaml` 当前为 `tools.enabled: false`、`allowed_tools: []`，且 `tools.searxng.base_url` 为空。模型范围和调用方工具授权由 Web「服务密钥」的 `allowed_models` / `allowed_tools` 管理；这是仓库配置文件状态，不据此推断用户线上配置一定相同。
- `docker-compose.yml` 通过 `EXISTING_DOCKER_NETWORK` 接入外部网络；本次已从 Gateway 容器验证 `searxng:8080` 可达。实际容器网络名称不影响当前已验证的服务 DNS 地址。
- 当前已确认应使用 Docker 服务名 `searxng`，不再依赖 `host.docker.internal` 的宿主机转发路径。
- 不要直接把 `127.0.0.1` 写入 Gateway 容器配置；容器内 loopback 指向 Gateway 容器自身。
- SearXNG Adapter 会在配置的 Base URL 后拼接 `/search`，因此当前实际部署的 Base URL 应配置为 `http://searxng:8080`，不能把 `/search` 重复写入。该地址使用 HTTP 且解析到 Docker 私网地址，必须在服务端配置中显式设置 `allow_insecure_http: true` 与 `allow_private_network: true`。这两项只用于固定的 SearXNG 执行器端点；不要关闭 DNS/IP 校验、重定向限制或代理隔离，也不要把环境专属 URL 写入通用默认配置。

## 4. 实施顺序

当前 Web 验收入口：
- 打开管理台「工具测试」，输入一个已启用、允许当前 Provider 服务范围且授予 `web.search` 的客户端服务密钥。
- 使用默认提示词或输入明确要求搜索当前信息的提示词，发起非流式请求。
- 页面显示请求结果与 `X-Request-ID`；点击「查看请求详情」，核对同一请求下是否存在 `web.search` 成功事件。
- HTTP 200 或模型返回文字本身不等于工具验收成功；必须确认工具事件存在且状态成功。
- 测试 Key 不写入 localStorage；不要把真实 Key 截图或提交到仓库。

性能测试边界：
- 性能与工具测试统一页面入口、共享客户端服务密钥，但请求协议与执行链路保持独立。
- 当前「性能测试」实现固定使用流式请求，而工具编排目前只接管非流式 Chat Completions；不能简单在现有流式基准请求上加 tools 字段。
- 后续若增加工具性能测试，应作为独立的非流式测试模式，分别记录模型各轮耗时、工具执行耗时和端到端耗时；不得把 SearXNG 网络耗时计入模型生成速度。
- 该模式放在 TOOL-09 真实闭环验收后实施，不影响现有流式性能基线。

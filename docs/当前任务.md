## 1. 任务目标

完成工具调用主链路的最终回归与真实环境验收，重点验证 Gateway 容器能够访问已部署的 SearXNG，并由真实模型发起 web.search 调用，最终在同一 request_id 下持久化工具审计事件并通过请求详情查询。

CI、Browser Smoke、真实 SearXNG 网络验收分别记录，不得用 Mock 或宿主机访问结果代替 Gateway 容器真实连通性。

## 2. 已有验收证据

- TOOL-08 已完成；Coordinator Observer、工具事件表、异步 Audit Writer、请求详情 API/UI 和清理生命周期已提交。
- Go CI [44044177513](https://github.com/Kasign/llm-gateway/actions/runs/44044177513) 全部成功，包含 Go 测试、race、静态检查、MariaDB 审计积压、并发/审计负载、故障注入/恢复、Docker 构建。
- Browser Smoke [44044177775](https://github.com/Kasign/llm-gateway/actions/runs/44044177775) 成功，工具调用详情列表、顺序、轮次、状态及键盘交互检查通过。
- 历史部署验证：宿主机访问 `http://127.0.0.1:8080/search`，请求 `format=json` 已返回 SearXNG JSON；该结果只证明宿主机访问成功。
- 历史部署记录中 Gateway 与 llama.cpp 曾使用 Docker network `1panel-network`；当前 Compose 通过 `EXISTING_DOCKER_NETWORK` 指定外部网络，实际部署值仍需以运行环境为准。

## 3. 当前发现与外部依赖

- 仓库中的 `config.yaml` 当前为 `tools.enabled: false`、`allowed_models: []`、`allowed_tools: []`，且 `tools.searxng.base_url` 为空。这是仓库配置文件状态，不据此推断用户线上配置一定相同。
- `docker-compose.yml` 已配置 `host.docker.internal:host-gateway`，但尚无证据证明 Gateway 容器可以通过 `host.docker.internal:8080` 访问宿主机 SearXNG。
- SearXNG 的 Docker 容器名、是否加入 Gateway 的外部网络、宿主机 8080 的监听绑定范围，当前仓库和历史记录均没有可靠证据。
- 不要直接把 `127.0.0.1` 写入 Gateway 容器配置；容器内 loopback 指向 Gateway 容器自身。
- 若采用宿主机网关地址访问 HTTP SearXNG，必须在服务端配置中显式允许 `allow_insecure_http` 与 `allow_private_network`；只有连通性确认后才调整实际部署配置，不把环境专属 URL 写成通用默认值。

## 4. 实施顺序

1. 核对当前 Gateway 实际 Docker network、SearXNG 的宿主机端口发布和容器名；不创建第二套 SearXNG，不改动现有模型/数据库/Redis 容器。
2. 从 Gateway 容器发起只读 JSON API 探测，确认 DNS、TCP、HTTP 状态和响应结构。首选验证宿主机网关路径：

   ```bash
   docker exec llm-gateway sh -lc 'wget -qO- "http://host.docker.internal:8080/search?q=Go%20release&format=json" | head -c 512'
   ```

   若失败，再依据实际 Docker network 与容器名判断是否应使用容器 DNS；不得猜测地址。
3. 连通性通过后，按真实部署配置启用工具：`tools.enabled=true`、`allowed_tools=[web.search]`、`allowed_models` 使用稳定 Gateway ModelKey；SearXNG Base URL 指向已验证的容器可达地址。
4. 使用支持标准 tool_calls 的真实模型和受限测试 Key 发起一次非流式请求，确认模型确实调用 web.search，而不是只返回普通文本。
5. 以同一个 request_id 检查 request_logs 与 request_tool_call_events：顶层请求只有一条；事件序号/轮次/状态/耗时/结果字节数正确；Token 总量使用所有模型轮次聚合。
6. 检查请求详情 API 和 Web UI 展示；确认审计表不含原始 query、arguments、完整结果正文、Authorization 或 Provider Key。
7. 覆盖授权拒绝、SearXNG 超时/不可用和普通非工具请求；确认事件状态/错误码正确，审计失败不改变模型响应。
8. 汇总真实环境、时间、配置来源、脱敏 request_id 和结果；失败项记录具体依赖，不以 Mock 通过代替真实验收。

## 5. 不可破坏的约束

- 只操作 `dev` 分支；不改默认分支和其他功能分支。
- 不创建新的 SearXNG 服务，不重建用户已有的 llama.cpp、MariaDB 或 Redis。
- 不把真实密码、API Key、完整搜索词或模型结果写入提交、日志或任务文档。
- 不伪造真实 SearXNG 响应；Mock 仅用于自动化测试。
- 不为了通过测试放宽 SSRF、DNS/IP 校验或 Runtime 授权边界。
- 实际部署配置与仓库示例分开处理；环境专属 Base URL 不写入通用示例默认值。
- 没有容器网络真实证据时，保持 TOOL-09 进行中，不标记端到端验收完成。

## 3. 当前调查

已确认可复用：

- `llama.RuntimeSnapshot`：模型、加载状态、RAM/VRAM；
- `Server.cpuUsagePercent`：主机 CPU 百分比；
- `upstreamRuntimeSnapshot`：已有短期缓存。

发现的关键问题：

- 直接在请求路径调用完整 RuntimeSnapshot 会增加上游 HTTP；
- CPU 首次采样包含约 200ms sleep，不能放入请求关键路径；
- 远程 Provider 没有本地 RAM/VRAM 事实，不能填 0；
- 管理台缓存不能直接宣称为请求时刻精确快照。

## 4. 下一步

先实现独立、低开销的运行时采样器，后台更新最近快照；请求分析只读取最近有效值。随后接入 RequestAnalysis，增加 complete/partial/unavailable 语义和历史兼容。

## 5. 约束

不修改普通 /v1 主流程，不增加每请求上游探测，不存储 Prompt/Response，不伪造性能值。

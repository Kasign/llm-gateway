## 1. 目标

修正 RequestAnalysis 中 Token 来源、速度来源与计算窗口混用的问题，并完整保留 llama.cpp timings 的 Prompt Eval/Decode 指标。优先修正数据语义和测试，不增加新的模型探测请求，不改普通请求行为。

## 2. 本任务范围

1. 将 Token 计数来源与速度来源分离表达，避免一个 Source 同时描述 usage/timings/派生速度。
2. 保留 `prompt_n`、`predicted_n`、`prompt_ms`、`predicted_ms`、`prompt_per_second`、`predicted_per_second`；对缺失、零值和非法值使用明确的可用性语义。
3. 修正 timings 解析有效性判断：不能因 Token 数或 Decode 速度为零，就丢弃仍然有效的 Prompt Eval/Decode 时长数据。
4. 仅在真实 Decode 速度可用时标记为 llama.cpp Decode 实测；Token 数/窗口派生速度必须单独标记。
5. 当没有语义匹配的 Decode 窗口时，不得把 upstream_ms 伪装成 Decode 窗口。
6. 更新管理详情的来源说明与摘要，保持旧 JSON 字段兼容，历史记录缺失字段显示 unknown。

## 3. 已实施

- `TokenHarvest` 分别保留 TokenSource、SpeedSource 和旧 Source 兼容字段。
- timings 解析改为逐字段验证；合法零值保留，负值、非数值和溢出值不作为有效测量。
- 非流式响应在解析 usage 后继续解析 timings；同一响应中的两类数据分别保留。
- 保留 llama.cpp Prompt Eval / Decode Token 数、耗时和速度原始字段。
- RequestAnalysis JSON 新增 `token_source`、`speed_source`、`llama_timings`；旧 `source` 继续保留用于历史兼容。
- llama.cpp Decode 实测速度不再伪造 Gateway 生成窗口；Gateway 派生速度只允许使用流式首条正文至最后事件的时间窗口。
- 非流式 `upstream_ms` 不再作为 Decode 速度计算窗口；没有匹配窗口时速度保持未知。
- 管理详情增加来源和 Prompt Eval / Decode 指标展示；OpenAPI 同步更新。

## 4. 当前回归覆盖

新增/调整测试覆盖：
- usage-only、timings-only、usage 与 timings 同时存在。
- Prompt timings 存在、Token 数为 0、Decode 速度缺失。
- timings 非法字段、零值、负值、溢出值。
- SSE 末包无换行时的 timings 解析。
- Token 来源与速度来源不一致。
- 非流式 upstream_ms 不得作为 Decode 窗口。
- 只有流式正文生成窗口可用于 Gateway 派生速度。
- 历史旧版 `analysis_json` 的 source 字段读取兼容。

# 调用成本统计与预算管理实施契约

> 状态：C1 进行中。本文是本功能的唯一实施范围说明；现有 Provider Token 预算和请求 Token 来源统计继续复用，不重复建设。

## 1. 目标

在现有请求审计、Provider 配置、API Key 权限和请求统计基础上，增加可追溯的费用核算与调用方预算控制。不得改变现有推理响应内容、流式时序或供应商凭据边界。

## 2. 已有能力（不得重复实现）

- `request_logs` 已保存 Provider、API Key ID/名称、实际模型、请求状态、Token 数量及 `analysis_json` 中的 Token 来源。
- `GET /api/requests/stats` 已支持 24h/7d/30d、Provider 筛选、请求/延迟/Token 来源聚合。
- 远程 Provider 已支持 UTC 自然日 Token 预算，计数基于 Redis；0 表示关闭。
- API Key 已支持 RPM、模型 ACL、过期时间和启停。
- 请求历史清理已存在，不能另建一套普通请求日志清理机制。

## 3. 费用核算规则

### 3.1 价格配置

价格以 Gateway 对外公开的模型 ID 为匹配主键，并关联 Provider ID。至少包含：

- Provider ID
- Gateway 模型 ID（公开模型 ID）
- 输入单价（每 1,000,000 tokens）
- 输出单价（每 1,000,000 tokens）
- 币种（首版统一 USD）
- 生效时间
- 价格版本/修订标识
- 创建/更新时间

价格必须使用十进制定点或等价的无精度损失方案存储和计算；禁止使用二进制浮点数累计金额。单价允许为 0，但不得为负数。相同 Provider、模型的有效价格区间不得重叠。

价格更新不得回算或改写历史请求费用。每条已核算请求应固化输入/输出单价、价格版本和费用结果，保证历史可复现。

### 3.2 Token 来源和费用状态

- 只有 `analysis_json.throughput.source` 明确为上游 usage，且输入/输出 Token 数完整、非负时，才允许标记为可计费并核算费用。
- `llama_timings`、`unknown`、缺失 usage、部分 Token 字段、未匹配价格均不得伪装为精确费用。
- 本地模型默认不计供应商费用；可展示 Token 使用量，但费用状态为 `not_applicable`。未来如需本地资源成本，应作为独立估算口径，不能混入供应商实际费用。
- 费用状态至少区分：`calculated`、`missing_usage`、`unknown_usage_source`、`missing_price`、`not_applicable`。
- 失败请求若上游没有可信 usage，费用未知；若上游确实返回了可信 usage，则按实际 usage 记录，不能因 Gateway 最终状态为错误就一概清零。

### 3.3 精度与公式

首版价格单位为 USD / 1,000,000 tokens：

`cost = input_tokens * input_price_per_million / 1000000 + output_tokens * output_price_per_million / 1000000`

存储精度应足以避免小额调用被过早舍入；汇总后再格式化显示。数据库金额列使用固定精度 DECIMAL，不使用 FLOAT/DOUBLE。

## 4. 预算规则

### 4.1 API Key 每日预算

在 API Key 管理中新增可选每日预算金额（USD）；0 或 NULL 表示关闭。按 UTC 自然日统计。预算消费以请求已确认的费用为准；预算准入需要采用保守策略，避免并发请求同时通过检查导致明显超额。

首版应明确采用“已结算费用 + 在途预留额度”的原子准入方式，或在无法可靠估算单次费用时明确拒绝启用金额预算，而不是用滞后统计伪装成硬限制。不得在缺少可靠价格/usage 的情况下承诺金额预算绝对不超额。

API Key 预算与 Provider Token 预算独立执行：任一已启用预算达到上限，都拒绝新请求；不影响已开始的请求。

### 4.2 准入顺序和失败策略

- 先完成身份认证、模型解析和 ACL 校验，再执行预算检查；不得在权限检查前产生预算副作用。
- 预算检查必须在任何上游请求和模型加载等副作用之前。
- Redis 是预算原子计数的共享存储。预算开启但 Redis 不可用时 fail-closed 返回 503；预算关闭时不应因预算逻辑额外依赖 Redis。
- 超限返回 429，错误码稳定且包含 `Retry-After`（若可确定 UTC 日界重置秒数）。
- 请求完成、取消、上游错误和客户端断开都必须释放未使用预留；结算与释放需要幂等，避免重复扣费或泄漏预留额度。
- 预算计数按 UTC 日界隔离；跨日运行中的请求仍归属其准入日，不能把旧日预留转入新日。

## 5. 统计能力

扩展现有请求统计体系，避免另建重复统计接口。保留既有 `/api/requests/stats` 的字段兼容性，并增加可选筛选维度：

- Provider ID
- Gateway 模型 ID
- API Key ID

新增费用汇总至少包含：

- 已核算请求数、费用合计、输入费用、输出费用
- 缺少 usage、来源未知、缺少价格、非计费请求数
- 按 Provider、模型、API Key 的聚合
- 当前统计窗口内的 Token 数和费用

费用汇总只能累加 `calculated` 记录。其他状态必须单独计数，不得按 0 美元展示成“已核算”。

API Key 统计只返回管理员会话可访问的聚合数据，不返回明文 Key、哈希或上游凭据。

## 6. 数据持久化与兼容

- 历史请求记录默认不回算费用；新增能力上线前的旧记录保持“未核算/不可用”，除非未来另行提供明确的历史补算任务。
- 每条请求费用记录应与请求生命周期最终写入保持一致；建议在 `request_logs` 增加费用状态、输入/输出单价快照、价格版本、费用金额和币种，避免异步审计链路产生跨表不一致。
- 价格配置应有独立持久化结构，支持历史版本和生效时间。
- 迁移必须兼容已有数据库，不能要求清库重建。
- 不在普通请求日志或错误信息中记录 API Key、Provider 密钥、提示词或响应正文。

## 7. 管理台范围

首版只增加必要的两个管理区域：

1. 模型价格管理：按 Provider/公开模型 ID 配置输入、输出单价和生效时间；编辑价格时创建新版本，不覆盖历史价格版本。
2. 成本统计：在现有请求统计页增加费用摘要和 Provider/模型/API Key 维度汇总；清楚展示未核算原因。

API Key 编辑/创建表单增加每日预算字段，并展示当日已用金额、预算上限和剩余额度。Provider 页面保留现有 Token 预算，不重复增加费用预算字段。

## 9. 验收标准

- 未配置价格、无可信 usage、本地 Token、旧记录均不会生成虚假费用。
- 修改价格不会改变已完成请求的费用。
- 费用计算不使用 float/double 累加。
- 并发请求不会绕过已启用的 API Key 金额预算；预算 Redis 故障时按 fail-closed 处理。
- 请求 ACL 拒绝、认证失败和模型解析失败不会占用预算。
- 取消、失败、客户端断开和重复 Finish 不会重复结算或泄漏预留。
- 流式响应正文和事件顺序与改动前一致。
- 新增管理 API 全部要求 Web Session，并同步 OpenAPI security、路由契约和测试。
- 完整执行 Go 测试、race、静态检查、OpenAPI 契约、前端构建及 Browser Smoke；真实供应商账单对账另行验收。

# 生产部署验收清单（1Panel / OpenResty / llama.cpp）

> 用途：在真实部署环境逐项验收；这份清单本身不代表已执行。记录日期、镜像/提交、环境差异和脱敏结果。禁止把 API Key、密码、完整 Authorization Header 或 Prompt 写入报告。

## 0. 变更前保护

- [ ] 记录当前镜像 tag/commit、Compose 配置版本和容器状态。
- [ ] 确认数据库备份与恢复方式可用；本轮不删表、不清库、不重置无关设置。
- [ ] 准备回滚到上一个已知可用镜像/提交的步骤。
- [ ] 检查真实配置文件是否被 Git 跟踪；不要上传 .env、Provider Key 或密码哈希。

## 1. 容器、配置和网络

```bash
docker compose ps
docker compose logs --since=10m --tail=200 gateway
curl -fsS http://127.0.0.1:8088/health
```

- [ ] Gateway、MariaDB、Redis 状态正常；日志无持续重启、配置解析错误或数据库连接失败。
- [ ] Compose 不再把密码哈希中的字符解释为环境变量；无相关插值警告。
- [ ] 从 Gateway 容器内访问实际配置的 llama.cpp 根地址和 Ollama 地址；不要将容器内的 localhost 误当作另一个容器。
- [ ] Gateway 发布端口只绑定预期的宿主机地址；不为方便测试而临时暴露管理端口到公网。

## 2. Web 密码保护与会话

- [ ] GET /api/auth/status 的保护状态符合预期；记录 password_source（不记录哈希）。
- [ ] 开启保护时：未登录访问管理 API 被拒绝；正确密码登录成功；错误密码被拒绝并触发限流保护。
- [ ] 关闭保护时：页面按设计自动建立会话；确认该入口只对受信网络开放，因为知道地址的人可操作管理功能。
- [ ] 在设置页修改密码、登出后验证新密码；旧密码失效。
- [ ] 重启 Gateway 后再次验证保护开关和密码仍然有效；数据库已有 web_admin_login 设置时，部署默认值不应覆盖它。
- [ ] 若使用临时 LLM_GATEWAY_WEB_LOGIN_RESET_FROM_ENV 恢复密码，确认恢复完成后已关闭该开关并重建容器。

## 3. Provider 和 llama.cpp 模型闭环

- [ ] Provider 页面加载配置；Key 只显示已配置/未配置或掩码，不回显明文。
- [ ] 对一个已授权的远程 Provider 执行连接测试和短请求；分别记录 HTTP 状态、模型 ID、响应是否符合协议，不记录密钥。
- [ ] 本地模型页能显示磁盘/注册模型，并区分“已加载”“未加载”和“无法确认”。
- [ ] 加载模型、查询加载状态、发送短请求、卸载/切换模型（如当前上游支持）均符合预期。
- [ ] Router 模式与单模型模式分别确认；检查 LLAMA_CPP_BASE_URL 是服务根路径，目录挂载在 Gateway 与 llama.cpp 侧一致。

## 4. SSE、慢模型和 OpenResty

- [ ] 从公网 HTTPS 地址发起流式请求，确认首段内容按 token/事件持续到达，而非全部缓冲到最后。
- [ ] 用实际慢模型观察首 Token 前等待时间；确认客户端、Gateway 整体时限与 OpenResty 空闲读写时限分别符合预期。
- [ ] 若允许长时间推理，确认 Gateway 的显式零整体超时设置已生效；OpenResty 的 proxy_read_timeout 是相邻读取间隔，不是总请求时限。
- [ ] 中途断开客户端，确认上游取消行为、审计状态与资源回收符合预期。
- [ ] 模拟上游不可达/重启，确认错误信息不泄漏内部地址或凭据，恢复后新请求可成功。
- [ ] 检查 OpenResty 关闭 buffering/cache/gzip，且 proxy_next_upstream 未对推理 POST 自动重放。

## 5. 审计、回滚与签字

- [ ] 成功、认证失败、上游失败和流式中断均产生可解释的调用记录；Gateway 状态与上游状态区分正确。
- [ ] 请求正文/流事件的保留策略符合部署配置；不为排查问题长期打开敏感 Payload 记录。
- [ ] 若任一关键项失败，保存脱敏日志与时间点，回滚应用版本；不要通过清空数据库掩盖问题。
- [ ] 验收记录包含：日期、提交/镜像、部署模式（宿主机/容器 OpenResty）、上游类型、结果、失败项与回滚结果。

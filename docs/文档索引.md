本文档是仓库文档导航。项目任务状态和当前进度以《整体任务规划》为唯一权威来源。

## 1. 推荐阅读顺序

1. [项目说明](../README.md)：产品定位、当前能力和快速启动。
2. [整体任务规划](整体任务规划.md)：全项目任务、顺序、状态和历史关联。
3. [当前任务](当前任务.md)：当前唯一执行任务的细节和进度（PERF-08 GGML Deep Profile）。
4. [产品能力技术方案](产品能力技术方案.md)：产品语义、目标架构、技术设计和验收标准。
5. [技术架构](architecture.md)：已实现架构和推理主流程。
6. [API / 配置 / 数据库契约](api-config-db-contracts.md) 与 [OpenAPI](openapi.yaml)：接口行为和机器可读契约。
7. [未关闭问题与后续验收](known-issues-and-followups.md)：已有功能缺陷、风险和运维验收缺口。
8. [任务历史](任务历史/README.md)：已完成任务的追溯记录。

## 3. 任务推进规则

1. 开始任何新任务前，先读取《整体任务规划》和《当前任务》，确认分支、基线和当前任务。
2. 任务必须先存在于《整体任务规划》，不得只在当前任务文档中临时新增任务。
3. 同一时间只允许一个当前执行任务；当前任务文档只描述这一任务。
4. 执行过程中只持续更新《当前任务》的证据、问题、进度和下一步。
5. 任务状态只在《整体任务规划》维护。其他文档可以引用状态，但不得维护第二份状态表。
6. 任务完成必须满足验收条件并记录提交、CI/测试和真实环境证据。
7. 任务完成时，同步更新总体状态、归档当前任务文档、建立下一任务文档内容，并更新所有关联链接。
8. 历史记录只用于追溯，不自动恢复为待办。
9. 如果发现缺失任务，先更新整体规划并说明新增原因，再开始执行。
10. 不把代码提交、测试跳过或 Mock 通过描述为真实环境验收通过。

## 4. 状态定义

| 状态 | 含义 |
|---|---|
| 待开始 | 已纳入范围，尚未开始 |
| 进行中 | 当前正在执行 |
| 已完成 | 所有约定验收条件均有证据 |
| 已阻塞 | 明确依赖阻止继续，必须记录解除路径 |
| 已取消 | 经明确决策从范围中移除 |

需要真实环境验证但尚无真实证据时，不得标记已完成；应保持进行中，或在确实无法继续时标记已阻塞。

## 5. 更新和提交规则

- 文档变更按一个可独立审查的逻辑组提交。
- 任务切换必须同步修改整体规划、当前任务和历史归档关联。
- 架构、API、配置和数据库事实分别更新其权威文档，不复制完整内容。
- 文档中引用的分支、提交、CI 和生产验收状态必须对应实际证据和准确时间。
- 中文任务文档使用稳定编号：TOOL-xx、PERF-xx、FREE-xx；历史文件名格式为“编号-中文任务名.md”。
